# ADR-0231: Strategikon and Enchiridion share one reference-workspace language

## Context

Battle-specific inspection has outgrown the narrow Controls panel. The complete
Run army already needs a full-pane ledger, relic collections need room to be
read, and future Battle-specific options should not be squeezed into command
tabs. At the same time, rules reference material must remain available from the
main menu when no Battle exists.

Returning to the main menu during a live Battle should feel like briefly
looking away from the board, not like abandoning it. The existing Play selector
also makes a resumable Run discoverable only after the player first chooses
Run.

## Decision

- **Enchiridion** is a main-menu destination immediately above Settings. Its
  initial sections are Units, Terrain, Relics, and Abilities.
  - Units demonstrates the canonical movement generated by the rules engine.
  - Terrain explains playable surfaces, gaps, obstacles, elevation, water, and
    fences. Knights hop gaps, fences, and intervening obstacles when their
    landing square is legal. Bishop rays inspect their diagonal cells; obstacles
    on adjacent non-diagonal cells do not block that diagonal path.
  - Relics lists every Run relic and opens a selected relic's description and
    player-lifetime **Times picked** and **Battles won while held** counts.
  - Abilities describes only what Discipline and Positioned do. It does not
    explain acquisition or progression.
- **Strategikon** is the Battle-context workspace. Its primary entry is one
  labeled action in the Controls panel title bar; it is not a fourth invariant
  top-right application control. Repeating that action returns to Battle.
- Strategikon's initial rail contains **Enchiridion**, **The Martial
  Prosopography** (Current Army), and **The Lipsanotheca** (Held Relics).
  Its buttons use the main-menu rail's canonical size, indentation, stone
  continuity, and interaction primitive while owning a Battle-specific
  inventory.
- Opening Strategikon or one of its destinations replaces only the Battle's
  board pane. The active Battle remains mounted and its clock continues. The
  right Controls column remains visible and is never overlaid, measured into,
  or used by Strategikon content.
- One shared reference implementation supplies Enchiridion in the main-menu
  host and the Battle host. Host composition may differ, but rules copy,
  section identities, relic selection, and statistics do not fork.
- The existing Run Army workspace is the implementation authority for
  Prosopography. The Lipsanotheca uses the canonical installed relic records,
  artwork, and descriptions; missing approved artwork remains explicit.
- Relic statistics are owner-scoped lifetime facts. The browser records
  deterministic pick and Battle-win events, keeps unsynced events locally, and
  submits them to an idempotent backend ledger when signed in. Server aggregates
  are merged with unsynced browser events without double-counting.
- Play prepends a dynamic **Continue** entry whenever an unresolved Run or
  persisted Battle exists. It names the actual activity in progress and routes
  directly back to it; normal Play choices follow.

## Consequences

- The main menu is a reliable home for timeless reference material, while
  Battle inspection remains one contextual action away.
- Controls retains immediate board commands instead of becoming an inventory
  or encyclopedia.
- The player can inspect army, relic, and rules information without unmounting
  or visually surrendering the Battle.
- Relic history survives completed and abandoned Runs for signed-in players and
  remains useful browser-locally for anonymous players.
- New Strategikon destinations must reuse the shared rail and respect the
  reserved Controls column rather than creating another menu language.
