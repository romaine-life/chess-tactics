# ADR-0316: Plagued icon candidates are reviewed in context

## Context

The initial Plagued Unit Ability reused the Capture crossed-swords glyph. That
preserved the UI kit but communicated combat rather than lasting disease and
attrition. A purpose-made generated glyph needs owner selection without
installing an arbitrary candidate or moving generated media bytes into Git.

## Decision

- Plagued receives a dedicated native 64×64 PixelLab icon family derived from
  the accepted game-icon visual language. The prompt asks for a cracked dark
  pawn and sickly rising miasma, and explicitly excludes weapons, shields,
  text, panels, potion bottles, and the modern biohazard symbol.
- Every generated option is a private live-media candidate at
  `ui/kit/icons/game/plagued.png`, with its exact prompt, PixelLab object and
  frame identity, reference slots, and native-resolution evidence retained as
  provenance.
- Owner review happens on the routable Studio surface
  `/studio?plaguedIconReview=1`. It mounts every option both in the real
  Enchiridion ability-icon seat and at native 64×64 size.
- Creating and displaying the review family does not install, accept, or
  substitute a candidate. The existing crossed-swords reference remains in the
  runtime until the owner selects an option; installation and runtime role
  wiring are a subsequent explicit change.

## Consequences

- The owner judges readability where the glyph will actually appear instead
  of from a detached contact sheet.
- Generated bytes remain private and live-storage-backed throughout review.
- The shipped Plagued ability remains visually unchanged until a specific
  candidate receives owner approval.
