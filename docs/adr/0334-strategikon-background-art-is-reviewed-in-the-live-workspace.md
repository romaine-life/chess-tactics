# ADR-0334: Strategikon background art is reviewed in the live workspace

## Context and Problem Statement

Strategikon correctly replaces only the Battle viewport and uses the shared
outer Chrome fill, but its large uncovered areas read as generic shell texture.
The owner requested a PixelLab artwork pass to add flavor while viewing the
workspace. A detached image would not prove whether the candidate preserves
rail, card, and text readability, while directly installing an arbitrary
generated image would skip owner judgment and the native-pixel gate.

## Decision Drivers

- Judge the artwork behind the real Strategikon rail and every real content
  destination.
- Keep the Controls column, attached shell body, and live reference content
  unchanged.
- Preserve exact PixelLab prompt and job provenance in live storage.
- Do not move a generated candidate into Git or the accepted runtime UI.
- Distinguish a scaled composition study from native 1x production art.

## Decision Outcome

Chosen: **mount one private PixelLab command-archive candidate in the live
Strategikon through an explicit review address**.

- The candidate occupies the decorative live-media slot
  `ui/workspaces/strategikon/background-command-archive.png`. Its generated
  bytes, exact prompt, PixelLab model, job id, seed, and dimensions are retained
  by the backend candidate record.
- `ShellWorkspace` owns an optional background-artwork layer. It sits above the
  ordinary outer fill and below the shared rail/body content; a workflow cannot
  recreate workspace attachment, clipping, or Controls-facing geometry to add
  artwork.
- `strategikonBackgroundReview=1` requests the exact private candidate on a real
  `/play/strategikon/*` or `/run/strategikon/*` route. The ordinary route does
  not fetch admin media and retains the installed generic fill.
- The first candidate is a subdued overhead command archive: worn dark work
  surface, maps, records, cord, seals, and measuring tools, with no people,
  readable writing, chess pieces, weapons, baked controls, or framing.
- The 688x384 candidate uses `cover` only for in-context composition
  calibration. That scaled presentation is explicitly not production
  acceptance under ADR-0076. Installation requires a later owner-selected
  native treatment (or a separately recorded exception) and a normal live-media
  review/accept transaction.
- Loading failure omits the decorative review layer. It never substitutes a
  repository fallback or changes normal Strategikon availability.

### Consequences

- The owner can judge contrast, crop, and atmosphere in the exact game surface.
- The shared shell remains the only owner of workspace fill geometry.
- The generated bytes remain private and no runtime pointer moves during
  exploration.
- A visually successful study still requires a separate production-resolution
  decision before installation.
